# Локальный голосовой сервис: результаты исследования и состояние проекта

**Срез:** 29 октября 2026 года. **Среда проверки:** Windows, RTX 3050 Laptop с 4 ГиБ VRAM, около 32 ГиБ RAM. **Цель:** локальные распознавание речи, синтез и клонирование голоса для будущего ИИ-агента. Для собственного кода и выбранных весов моделей требуется Apache-2.0.

Этот документ описывает текущую реализацию и проверенные выводы. Числа ниже относятся к конкретному ноутбуку и тестовым записям; они не являются сравнительным бенчмарком качества моделей.

## Главные выводы

1. На данном оборудовании работает модульная схема: файловый ввод → Qwen3-ASR → текст → выбранный TTS → WAV. Единая модель для всех этапов в проекте не развёрнута.
2. Qwen ASR определяет язык автоматически и возвращает текст на языке исходной речи. Добавлен отдельный русский Whisper Stage AW с CTranslate2 INT8/FP16; перевод отключён. На пользовательской записи качество ещё не сравнивалось, систематической оценки ошибок пока нет.
3. Для TTS доступны MOSS Nano на CPU, Qwen CustomVoice, Qwen Base с клонированием и CosyVoice 3 с клонированием. MOSS быстрее на повторных запросах, но на проверенном русском примере пропускал и искажал слова. Qwen и CosyVoice требуют отдельного GPU-процесса на каждый запрос.
4. Клонирование здесь означает генерацию с условием на короткую запись, **без дообучения весов**. Один сохранённый WAV используется всеми тремя движками клонирования. Для CosyVoice нужна точная расшифровка образца; для Qwen Base она необязательна, но включает более информативный режим ICL.
5. CosyVoice помещается на 4 ГиБ лишь с небольшим запасом. Зафиксирован один нативный сбой `c10.dll` (`0xC0000005`) и последующие успешные запросы. Причина сбоя не установлена; стабильность требует отдельной серии проверок.
6. Прямой голосовой диалог, оркестратор агентов и анализ видеокадров не реализованы. Веб-запись заканчивается перед отправкой: это файловый ASR, не потоковая беседа.

## Схема и сценарии

```text
Браузер (файл / запись микрофона / текст)
    ↓ HTTP, aiohttp, один общий слот обработки
Аудио/видео → PyAV → mono 16 kHz → Qwen3-ASR-0.6B → транскрипт
Текст → нормализация дат/времени/температур → один из четырёх TTS → WAV
                                                    ↓
                                         проигрывание / скачивание
```

| Сценарий | Сейчас | Что ещё нужно |
|---|---|---|
| Прямой голосовой диалог | Файловые ASR и TTS | Потоковый транспорт, управление ходом разговора, агент/LLM, прерывание ответа |
| Голосовой промпт агенту | Запись, загрузка и текст ASR | Передача текста оркестратору |
| Озвучивание текста | Реализовано: текст/TXT → WAV, плеер и скачивание | Доработка качества под реальные примеры |
| «Содержание видео» | Расшифровывается только звуковая дорожка | Для пересказа нужен агент; для понимания изображения нужна отдельная модель анализа кадров |

Реализация: `src/stt_tts/server.py` (HTTP), `engine.py` (ASR), `tts.py`/`tts_worker.py` (Qwen), `moss.py`, `cosyvoice.py`/`cosyvoice_worker.py`, `voices.py`, `text_normalization.py`. Исходники: `C:\Users\andre\stt_tts`; модели, окружения, кэши, временные файлы, голоса и результаты: `D:\Games\STT_TTS_project`. Основное окружение, Qwen TTS и CosyVoice изолированы друг от друга из-за разных версий `transformers`.

## Как устроено распознавание

Сервер принимает один аудио- или видеофайл до 64 МиБ и 10 минут, берёт первую аудиодорожку, декодирует через PyAV и переводит в mono 16 кГц. Qwen ASR получает части около 25 секунд, разделённые по низкой энергии сигнала, и обрабатывает их по одной. Язык определяется отдельно для каждой части (`language=None`); готовые тексты соединяются. Это не точное выравнивание по словам: временные метки обозначают только границы частей. Разрезание может повредить слова у границы, а автоопределение языка иногда ошибается. Принудительный язык и перевод сервис не применяет. Необязательное поле API `context` может передать названия или термины, но веб-форма его сейчас не показывает.

Пользователь сообщил о слабом качестве распознавания записанного текста. Известные синтетические тесты показывают работоспособность и сохранение исходного языка, **но не измеряют WER/CER на пользовательской записи**. Улучшение ASR отложено до появления эталонной записи и корректной расшифровки для сравнения.

## Синтез, клонирование и хранение голоса

Перед синтезом собственный нормализатор превращает некоторые русские даты, время и диапазоны температур в слова. Он устраняет проверенные ошибки вроде «26 октября», «7:00», «24 и 25 октября», `+10−12 °С`. Это набор контекстных правил, а не полный грамматический анализатор; десятичные температуры и неоднозначные записи остаются ограничением. Новый текст ограничен 2000 символами и при необходимости делится на фрагменты.

Образец голоса длительностью 3–30 секунд (до 16 МиБ) декодируется и сохраняется как WAV PCM16, stereo 48 кГц в `D:\Games\STT_TTS_project\voices\clone-<id>.wav`. Рядом лежит JSON с именем, идентификатором, длительностью и предварительно вычисленными MOSS-кодами. Оригинальный загруженный файл временный. Сохранённый образец удаляется только по явной команде удаления голоса. Использовать следует свой голос или запись с разрешением владельца.

| Движок | Что извлекает из образца при синтезе | Что даёт текст образца |
|---|---|---|
| MOSS | Предварительно сохранённые аудиокоды ONNX-кодека | В текущем пути не используется |
| Qwen Base, пустой `ref_text` | Speaker embedding; режим `x_vector_only_mode=True` | Не нужен |
| Qwen Base, заполненный `ref_text` | Speaker embedding + аудиотокены образца; режим ICL | Точная расшифровка служит примером «эти слова → эта речь» |
| CosyVoice 3 | Speaker embedding, речевые токены и акустические признаки; zero-shot prompt | **Обязательная** точная расшифровка образца |

Для Qwen и CosyVoice признаки вычисляются заново на каждый запрос и переиспользуются между фрагментами этого запроса. Постоянного «обученного клона», нового checkpoint или обновления весов модели нет. Кнопка «Распознать выбранный образец» использует текущий Qwen ASR; её результат нужно вручную проверить, особенно перед CosyVoice.

## API, эксплуатация и ограничения

- `POST /api/transcribe`: multipart `file`, необязательный `context`; непустой `language` отклоняется. Возвращает текст, автоопределённый язык и границы частей.
- `POST /api/tts`: JSON с `text`, `engine` (`moss`, `qwen`, `qwen_clone`, `cosyvoice`), `speaker`; для Qwen Base и CosyVoice дополнительно `ref_text`. Возвращает WAV и метаданные.
- `GET/POST /api/voices`, `GET/DELETE /api/voices/{id}`: работа с сохранёнными образцами.
- `GET /health`: состояние сервиса и установленных движков.
- Общий слот обрабатывает один запрос ASR/TTS/создания голоса за раз; второй получает HTTP 429. Перед Qwen/CosyVoice ASR выгружается из GPU. MOSS на CPU может работать при загруженном ASR. TTS worker ограничен 15 минутами.
- По умолчанию сервер доступен только на `127.0.0.1:8090`. Для доступа по сети предусмотрены `API_TOKEN` и HTTPS-прокси; персональные аккаунты, production rate limiting и развёртывание для многих пользователей ещё не реализованы.

Исходники и тесты Apache-2.0. Карточки выбранных весов Qwen, MOSS и CosyVoice указывают Apache-2.0. **Вся сборка не состоит исключительно из Apache-2.0 компонентов:** PyTorch, PyAV, NumPy, подмодули и другие зависимости имеют собственные лицензии. Перед распространением сборки нужен отдельный аудит зависимостей и соответствующих уведомлений.

## Следующие инженерные задачи

1. Собрать набор пользовательских аудиозаписей с эталонной расшифровкой, измерить WER/CER и отдельно ошибки на границах фрагментов, языках и шуме. Только после этого выбирать улучшение ASR.
2. Проверить сходство клонирования слепым прослушиванием на реальных разрешённых образцах. Обратное ASR не заменяет такую оценку.
3. Повторить CosyVoice под контролируемой нагрузкой и определить причину нативного сбоя; не считать его исправленным по одному успешному повтору.
4. Для прямого диалога добавить транспорт реального времени, VAD/turn taking, оркестратор и потоковый вывод аудио. Для видеокадров — отдельное зрительное звено.
