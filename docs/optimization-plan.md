# Программа ускорения Qwen ASR и TTS

Цель: уменьшить ожидание **на 70%** относительно измеренной исходной версии
для одинаковых входов на этом ноутбуке (RTX 3050 4 ГБ), сохранив качество.
Это целевой показатель, не достигнутый результат. Сравниваем именно время
от отправки запроса до первого полезного ответа и до полного ответа;
скорость произнесения готового WAV в метрику не включаем.

## Исходная база

Из `D:\Games\STT_TTS_project\evaluation\2026-10-29`:

| Сценарий | Исходное время | Цель −70% | Что измерено |
|---|---:|---:|---|
| ASR, русская запись 12,8 с | 2,495 с | ≤0,749 с | Только инференс, без загрузки и декодирования файла |
| ASR, пользовательская запись 32,3 с | 7,122 с | ≤2,137 с | Только инференс, без загрузки и декодирования файла |
| TTS, встроенный голос, медиана трёх фраз | 49,398 с | ≤14,819 с | Весь TTS-запрос, включая старт процесса и загрузку модели |
| TTS, клонированный голос, медиана трёх фраз | 51,851 с | ≤15,555 с | Весь TTS-запрос, включая старт процесса, модель и подготовку образца |

ASR и TTS здесь измерены по-разному. Перед заявлением об общей экономии
нужно снять единую базу *время от HTTP-запроса до ответа* для файла, записи
микрофона, встроенного голоса и клона. Измерения повторить не менее 10 раз
для холодного и тёплого состояния; отчёт: медиана, p95, время первого текста/
аудио, длительность входа/выхода, размер GPU-памяти, CER/WER для ASR и ошибки
произношения/повторов TTS. Один удачный прогон не считается достижением цели.

## Этапы

| Приоритет | Работа | Ожидаемый эффект | Проверка |
|---|---|---|---|
| 1 | Профилировать время декодирования файла, загрузки весов, подготовки текста/голоса, генерации и записи WAV. Добавить длительности этапов в метаданные и журнал без текста/аудио. | Установить долю каждого узкого места. | Сумма этапов согласуется с временем HTTP-запроса. |
| 2 | Перевести Qwen TTS из `subprocess.run` на долгоживущий worker. Держать одну выбранную модель на GPU между запросами; переключать CustomVoice/Base по явному правилу освобождения памяти. | Убрать повторную загрузку на каждом запросе; главный кандидат на −70% для последовательного TTS. | Второй и последующие одинаковые запросы; отсутствие роста VRAM и ошибок переключения с ASR. |
| 3 | Для каждого сохранённого голоса один раз вычислять и хранить подготовленный clone prompt, привязанный к версии модели, WAV и расшифровке; пересчитывать при изменении любого из них. | Ускорить повторное клонирование без повторного разбора образца. | Результат совпадает по тембру и словам; кэш инвалидируется корректно. |
| 4 | Выдавать готовые аудиофрагменты по мере генерации и запускать воспроизведение до завершения всего текста. На первом этапе оставить скачивание полного WAV. | Сократить время до первого звука, особенно для длинного текста. | Пользователь слышит первый фрагмент раньше полного ответа; порядок и паузы не нарушены. |
| 5 | Убрать повторное полное ASR каждые 2 секунды в живом режиме. Использовать VAD/конец фразы и инкрементальные фрагменты с ограниченным перекрытием; проверить, поддерживает ли используемый Qwen runtime настоящее сохранение состояния между фрагментами. | Снизить повторные вычисления и задержку предварительного текста. | Те же фразы без потерь и дублей; CER/WER не ухудшаются. |
| 6 | Проверить FP16/квантование, альтернативный inference backend и размеры ASR/TTS фрагментов на RTX 3050. Внедрять только после сравнения качества. | Дополнительное ускорение инференса; эффект неопределён. | Не хуже исходного качества на русских, английских и смешанных записях; отсутствие OOM. |

## Режимы на 4 ГБ VRAM

ASR и TTS не следует без проверки держать одновременно на видеокарте.
Планировщик поддерживает один активный GPU worker: для серии распознаваний
оставляет ASR загруженным, для серии озвучиваний — TTS. Переключение движка
измеряется отдельно. Если переключения частые, цель −70% для *каждого*
чередующегося запроса может оказаться недостижимой без большего объёма VRAM
или отдельного GPU. Не маскировать это цифрами только для тёплой серии.

## Критерий завершения

Для каждого из четырёх сценариев отдельно: медиана HTTP-ожидания ≤30% базы,
p95 не вырос относительно базы, CER/WER ASR не ухудшились, в TTS нет новых
пропусков, повторов и ошибок нормализации. Для озвучивания дополнительно
сравнить время до первого звука и прослушать встроенный и пользовательский
голос. Если цель не достигнута на 4 ГБ VRAM, указать достигнутый процент и
аппаратное ограничение, а не объявлять план выполненным.
