## Четыре сценария проекта

| Сценарий | Цепочка | Состояние |
|---|---|---|
| Прямой диалог | Микрофон → транспорт → ASR → агент → TTS → динамики | Есть файловые ASR и TTS; нужны агент и потоковый транспорт |
| Промпт голосом | Запись → API → ASR → текст запроса → агент | Реализованы запись, API и ASR; передача агенту — следующий этап |
| Озвучивание текста | Текст → API → TTS → WAV | Реализованы ввод, загрузка TXT, проигрывание в браузере и скачивание |
| Содержание видео | Видео → декодирование звука → ASR → транскрипт → агент | Реализована расшифровка звука; пересказ агентом — следующий этап |

ASR преобразует речь в текст. Агент отвечает на этот текст и вызывает инструменты.
TTS превращает готовый текст ответа в речь. Если требуется понять происходящее
в видеокадрах, к четвёртому сценарию нужно отдельно добавить анализ изображений.

### Пробный Nemotron 3.5 ASR Streaming 0.6B

В списке распознавания доступен Nemotron 3.5 ASR Streaming 0.6B. Его веса
распространяются под **OpenMDW 1.1**, а не Apache 2.0; это отдельный
экспериментальный движок, установленный на D:. Исходный код сервиса остаётся
Apache 2.0. Для повторной установки запусти из PowerShell:

```powershell
cd C:\Users\andre\stt_tts
.\scripts\setup-nemotron.ps1
.\start.ps1
```

NeMo-Speech.cpp и GGUF-веса находятся в `D:\Games\STT_TTS_project\tools\nemo-speech`
и `D:\Games\STT_TTS_project\models\nemotron`. Первый запрос загружает модель;
последующие используют уже загруженный процесс. Перед Qwen TTS или другим ASR
движок выгружается для освобождения видеопамяти. Язык определяется автоматически,
перевод не выполняется. Поле контекстной подсказки для Nemotron пока не используется.
В режиме микрофона веб-сервис пока повторно распознаёт накопленную фразу;
нативный кэшированный потоковый API NeMo-Speech.cpp ещё не подключён.
Для CPU-режима запусти сервер с `$env:NEMOTRON_DEVICE='cpu'`.
Загрузи WAV/MP3/WebM/MP4 либо запиши микрофон и нажми «Распознать».
Язык определяется автоматически для каждой части записи. Расшифровка сохраняет
язык исходной речи: английский → английский, французский → французский.
Принудительный выбор языка и перевод отключены. Это правило обработки,
а не гарантия отсутствия ошибок модели; возможна нормализация пунктуации и чисел.
Первый ASR-запрос загружает модель в память. Она остаётся загруженной
при синтезе MOSS и выгружается перед синтезом Qwen.
По умолчанию используется GPU, если CUDA доступна; иначе CPU.

## Озвучивание текста

В блоке «Текст → речь» введи текст или загрузи `.txt` в UTF-8, выбери голос
и нажми «Озвучить текст». Также можно взять текст готовой расшифровки кнопкой.
После обработки появятся проигрыватель и ссылка «Скачать WAV».
В интерфейсе по умолчанию выбран MOSS и женский голос Bella.
У MOSS доступны Bella, Ava, Adam, Nathan; у Qwen — девять голосов,
по умолчанию Serena. При смене движка список голосов меняется.
Максимум 2000 символов за запрос; длинный текст синтезируется частями
с короткими паузами между ними. WAV: PCM16; MOSS — 48 kHz, стерео,
Qwen и CosyVoice — 24 kHz, моно. Текст не переводится. MOSS заявляет 20 языков,
Qwen — 10, включая русский, английский и французский. Произношение и акцент
зависят от выбранного голоса. Для клонирования выбери MOSS или Qwen Base.

Перед синтезом работает собственный нормализатор русских дат, времени и температур
(`text_normalization.py`, Apache-2.0), до разделения текста на части.
Он передаёт модели слова вместо неоднозначных цифр:

- «Сегодня 26 октября» → «Сегодня двадцать шестое октября».
- «Встреча 26 октября» → «Встреча двадцать шестого октября».
- «в 7:00» → «в семь часов», «в 7:05» → «в семь часов пять минут».
- «с 7:00 до 8:30» → «с семи часов до восьми часов тридцати минут».
- «24 и 25 октября» → «двадцать четвёртое и двадцать пятое октября»;
  «Встречи 24 и 25 октября» → «Встречи двадцать четвёртого и двадцать пятого октября».
- «+10−12 °С» → «от плюс десяти до плюс двенадцати градусов Цельсия».
- «−10−12 °С» → «от минус десяти до минус двенадцати градусов Цельсия».

Поддерживаются русские названия месяцев, даты ДД.ММ.ГГГГ / ДД/ММ/ГГГГ /
ГГГГ-ММ-ДД, год и время ЧЧ:ММ[:СС]. Падеж определяется по простым
контекстным правилам; это не полный синтаксический анализатор русского языка.
Без контекста «26 октября» трактуется как название даты, «7:00» — как
семь часов, а не длительность семь минут. Для неоднозначных таймкодов,
сокращённых диапазонов и сложных предложений лучше явно писать словами.
Иностранные предложения проверяются отдельно; ссылки, код и неверные
календарные значения правила не меняют. Текст в поле ввода остаётся исходным.
В перечислениях дат общий месяц применяется ко всем дням, поддерживаются
запятые и союзы «и», «или», «либо». Падеж берётся из общего контекста.
Температуры: целые числа до 999 по модулю, °C/°С/℃ и °F/°Ф/℉,
одиночные значения и диапазоны с дефисом, тире, минусом, многоточием или «до».
В погодной записи +10−12 обе границы положительны, −10−12 — отрицательны;
для перехода через ноль знак второй границы нужно указывать явно: −10…+12.
Десятичные температуры пока не раскрываются словами.
В метаданных WAV возвращаются `text_normalization` и `normalization_applied`.

MOSS работает через CPUExecutionProvider и остаётся в RAM после первого запроса.
Его путь инференса использует ONNX Runtime, NumPy и SentencePiece без PyTorch.
ASR при этом может оставаться на GPU. Число потоков CPU: `MOSS_CPU_THREADS`,
по умолчанию 4. Для повторяемого сравнения генератор MOSS получает seed=1234
на каждый запрос. Встроенные голоса берутся из официального manifest модели.
Используется официальный `ort_cpu_runtime.py`; более тяжёлый upstream wrapper
с импортами torch/torchaudio и WeTextProcessing не используется.
Нормализация текста — общая собственная, как у Qwen.

Установка MOSS: `scripts/setup-moss.ps1`. ONNX-модель и кодек размещаются на D,
ревизии весов и исходного runtime закреплены в `models/moss.json`.
Git-репозиторий с Apache LICENSE: `D:\Games\STT_TTS_project\tools\moss-tts-nano`.
Адаптированный manifest с абсолютными локальными путями создаётся отдельно
в `models/moss-runtime`; исходные HF snapshot-файлы не изменяются.

Qwen на RTX 3050 4 GB работает по очереди с ASR: перед ним ASR выгружается,
а Qwen-TTS запускается отдельным скрытым процессом. После синтеза он завершается
и освобождает GPU-память. Следующее распознавание заново загрузит ASR.
Каждый синтез Qwen включает загрузку модели, в отличие от повторных запросов MOSS.
Второй одновременный запрос любого движка получает 429.
Общий предел ожидания TTS — 15 минут; при превышении нужно сократить текст.

Изолированное окружение TTS: `D:\Games\STT_TTS_project\envs\tts`.
Оно нужно из-за несовместимых точных зависимостей: qwen-asr 0.0.6 использует
Transformers 4.57.6, qwen-tts 0.1.1 — 4.57.3. Установка: `scripts/setup-tts.ps1`.
Веса с вложенным аудиотокенизатором занимают около 2,5 GB и скачиваются на D.
Зафиксированная ревизия: `models/tts.json`. Прямые зависимости TTS:
`requirements/qwen-tts.txt`.
Для CPU-режима TTS: `$env:TTS_DEVICE='cpu'` перед запуском сервера.

Для Qwen текст и WAV временно создаются в `D:\Games\STT_TTS_project\tmp\tts-*`
и удаляются после генерации. MOSS собирает WAV в оперативной памяти.
Аудио остаётся в памяти открытой страницы;
для сохранения скачай его до обновления/закрытия вкладки. Папку скачивания
выбирает браузер. Сервер синтезирует локально из подготовленных весов, без API облачного TTS.

Явный CPU-режим (медленнее):

```powershell

.\start.ps1
```

Вернуться к автоматическому выбору: `$env:ASR_DEVICE='auto'`.
Остановка сервера: Ctrl+C в его терминале.
Если сервер был запущен в фоне при первоначальной настройке, остановить его

Пока он работает, повторно вызывать `start.ps1` не нужно.

## API

- `GET /health` — состояние модели и доступные функции.
- `POST /api/transcribe` — multipart: `file`, необязательный `context` с именами/терминами.
- `GET /api/stream` — WebSocket для живого распознавания Qwen. Сначала JSON
  `{"type":"start","sample_rate":16000,"token":"..."}`, затем бинарные порции
  моно PCM16 LE с частотой 16 кГц (не длиннее 1 секунды). Сервер возвращает
  `ready`, `partial`, `final`; JSON `{"type":"flush"}` завершает фразу,
  `{"type":"stop"}` завершает сеанс. `utterance_id` связывает промежуточный и
  окончательный варианты. Одна фраза — до 30 секунд, сеанс — до 10 минут.
  Поле `engine`: `qwen` (по умолчанию, автоопределение языка) или `whisper`
  (русская речь, без перевода). Для Whisper `context` не поддерживается.
  Непустое устаревшее поле `language` отклоняется с HTTP 400: принудительный язык отключён.
- Ответ: `text`, `language`, `device`, длительность записи и время обработки,
  `simulated=false`, `language_mode=auto`, сегменты с определённым языком
  и приблизительными границами частей. `language` в ответе — результат автоопределения.
- `POST /api/tts` — JSON: `{"text":"Привет!","engine":"moss","speaker":"Bella"}`.
  Значение engine: `moss`, `qwen`, `qwen_clone` или `cosyvoice`.
  Для совместимости старых API-клиентов
  отсутствие engine означает qwen; веб-интерфейс явно отправляет выбранный движок.
- `PUT /api/voices/{id}/transcript` — JSON `{"ref_text":"Точная расшифровка образца"}`.
  Сохраняет текст рядом с WAV на D:. Для Qwen Base и CosyVoice сервер берёт
  сохранённый текст, если `ref_text` не передан в запросе. Образец аудио
  загружается **один раз** при создании голоса; затем выбирается его ID.
  Голос по умолчанию: Bella для MOSS, Serena для Qwen.
  Ответ — `audio/wav` с именем `speech.wav` и заголовком `X-TTS-Metadata`
  (JSON: голос, модель, устройство, длительность и время обработки).
  Тот же Bearer-токен, что у ASR, если включена авторизация.

```powershell
curl.exe -F 'file=@D:\recording.wav' http://127.0.0.1:8090/api/transcribe

# Русский Whisper Stage AW после установки:
curl.exe -F 'file=@D:\recording.wav' -F 'engine=whisper' http://127.0.0.1:8090/api/transcribe

Для живого распознавания нажмите «Начать живое распознавание» в веб-интерфейсе.
Микрофон передаёт 16 кГц PCM16 по WebSocket порциями по 200 мс; браузер
обнаруживает паузы и завершает фразы. Промежуточный текст пересматривается
по мере поступления звука; окончательный текст появляется после паузы или
нажатия «Завершить». Qwen предзагружается в фоне при запуске сервера. Для
отключения предзагрузки установите `ASR_PRELOAD=0` перед стартом. После
использования GPU-движка TTS Qwen ASR снова загружается при следующем
распознавании, поскольку обе модели не помещаются одновременно в 4 ГБ VRAM.

Повторяемый замер: `python scripts/benchmark-stream.py D:\path\to\speech.wav --seconds 5`
(при установленном `PYTHONPATH=src`). На тестовом образце
первый промежуточный текст появился через 2,4–3,0 с после начала передачи,
окончательный текст пятсекундной фразы — через 6,2–6,6 с. Это локальные
измерения на уже загруженной модели; качество микрофона и нагрузка могут
менять результат.
```

Аудио/видео декодируется локально через PyAV. Отдельный ffmpeg.exe не нужен.
Из видео берётся первая звуковая дорожка; видеокадры не анализируются.
Максимум 64 МиБ / 10 минут. Записи делятся на части до 25 секунд, batch=1 —
это снижает риск OOM на RTX 3050 4 GB. Временные метки — границы частей,
не точная разметка слов. Разделение может влиять на распознавание пограничных слов.
Обрабатывается один запрос за раз; при занятости API возвращает 429.

Это файловое распознавание, не потоковый ASR. Запись с микрофона сначала
заканчивается, затем отправляется на сервер. Прямой разговор будет отдельным этапом.

## Сохранение образца голоса

В разделе «Текст → речь» раскрой «Мои голоса — клонирование по образцу».
Укажи имя, загрузи 3–30 секунд чистой речи одного человека (до 16 МиБ)
и нажми «Сохранить голос». Перед сохранением можно прослушать образец.
Голос автоматически выбирается в текущем движке клонирования и сохраняется после
перезапуска сервера. Образец доступен MOSS, Qwen Base и CosyVoice 3; в Qwen
CustomVoice эти голоса недоступны. Дополнительное обучение не требуется.

Образец декодируется PyAV в stereo 48 кГц, ONNX-кодировщик MOSS вычисляет
аудиокоды. WAV и JSON с кодами сохраняются в `D:\Games\STT_TTS_project\voices`.
Исходная загрузка временная и удаляется после обработки. Сохранённый WAV и коды
остаются до нажатия «Удалить выбранный голос». Используй свой голос или запись
с разрешением владельца. Обработка выполняется локально. Тишина отвергается,
но автоматической проверки числа говорящих и качества речи пока нет.

API (тот же Bearer-токен, если включён):

- `POST /api/voices`: multipart-поля `name` и `file`, ответ 201 с `id`.
- `GET /api/voices`: список без аудиокодов.
- `GET /api/voices/{id}/audio`: нормализованный WAV образца.
- `DELETE /api/voices/{id}`: удаление WAV и кодов.
- `POST /api/tts`: JSON `{"engine":"moss","speaker":"clone-...","text":"Привет"}`.

Подготовка голоса использует общий слот с распознаванием и синтезом.
При занятом сервисе создание и удаление возвращают 429. Тестовый синтетический
образец 12,803 с подготовился за 12,12 с (включая холодную загрузку);
5 с новой речи с ним — за 3,29 с на CPU. Это проверка работоспособности,
а не оценка сходства с живым человеком. Искажения русских слов возможны.

## Qwen Base: клонирование

Подготовка: `scripts/setup-qwen-clone.ps1` (после установки окружения `scripts/setup-tts.ps1`).
Официальные веса Apache-2.0 скачиваются на D; SHA закрепляется в
`models/qwen-clone.json`. MOSS и Qwen CustomVoice остаются доступными.

Выбери «Qwen Base — клонирование · GPU» и сохранённый голос. Используется тот же
WAV образца, что у MOSS; его MOSS-коды в Qwen не передаются.
Без расшифровки включён `x_vector_only_mode=True` (только speaker embedding).
Если заполнено «Что сказано в образце», включается режим с аудиокодами и точным
текстом образца (ICL). Текст можно ввести вручную или получить кнопкой
«Распознать выбранный образец», затем проверить и исправить. При смене голоса
поле очищается, чтобы не использовать чужую расшифровку. Текст образца не
нормализуется; нормализуется только новый текст для озвучивания.

API: `POST /api/tts` с JSON
`{"engine":"qwen_clone","speaker":"clone-...","text":"Новый текст","ref_text":"Текст образца"}`.
`ref_text` необязателен, до 2000 символов. Метаданные содержат `clone_mode`:
`speaker_embedding` или `reference_text`. Профиль Qwen готовится один раз на
запрос и используется для всех его частей; между запросами не кэшируется.
Путь к образцу определяется сервером по ID, внешние URL и пути API не принимает.
Перед Qwen ASR выгружается; после завершения отдельный TTS-процесс освобождает
VRAM. Общий слот, таймаут и удаление временных данных такие же, как у CustomVoice.

Проверено на RTX 3050 Laptop 4 ГБ: режим только по тембру, синтетический образец
12,803 с, новый текст «Привет. Это проверка нового голоса.» — 3,28 с WAV,
81,82 с обработки с загрузкой модели, пик выделенной памяти PyTorch 2267,1 МиБ.
Это не общий расход памяти всей видеокарты и не гарантия времени для других записей.
В браузере также проверен режим с расшифровкой: «Привет. Это проверка клонирования
голоса Qwen.» — 4 с аудио за 32,13 с с загрузкой модели. Проверены кнопка ASR
для образца, очистка расшифровки при смене голоса, воспроизведение и WAV-ссылка
на тот же аудиофайл. Qwen CustomVoice и клонирование MOSS прошли отдельные
реальные запросы после изменений. Транспорт, валидация и прежние функции:
Тесты проекта проходят. Эти образцы синтетические; сходство с живым человеком
нужно оценивать на его записи.

## CosyVoice 3: клонирование

Выбери «CosyVoice 3 — клонирование · GPU», сохранённый голос и заполни точный
текст образца. Можно нажать «Распознать выбранный образец» и исправить результат.
Для этого движка расшифровка обязательна. Новые WAV, проигрывание и скачивание
появляются в том же блоке. Исходные профили MOSS и Qwen не меняются.

Подготовка: `scripts/setup-cosyvoice.ps1`. Отдельное окружение — `envs/cosyvoice3` на D;
PyTorch 2.8.0/cu126, Transformers 4.51.3. Список пакетов:
`requirements/cosyvoice.txt`, закреплённые версии зависимостей —
`requirements/cosyvoice.lock.txt`. Сборка старого Whisper требует
setuptools 78.1.0 из `requirements/cosyvoice-build.txt`.
Whisper здесь используется для вычисления mel-признаков; его ASR-веса не скачиваются.
Распознавание сервиса по-прежнему выполняет Qwen3-ASR.

Официальный runtime закреплён на commit `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`
в `D:\Games\STT_TTS_project\tools\cosyvoice3`, подмодуль Matcha — по commit
родительского репозитория. Исходники upstream не редактируются. Модель и код
CosyVoice — Apache-2.0; подмодули и библиотеки имеют собственные лицензии.
Скачиваются только файлы инференса: базовый LLM (без второго RL-checkpoint),
flow, HiFT, campplus, speech tokenizer v3, CosyVoice-BlankEN и конфигурация.
`prepare_cosyvoice` закрепляет SHA модели в `models/cosyvoice.json`, докачивает
по диапазонам и проверяет SHA-256 каждого LFS-файла. Части находятся в D/tmp
и удаляются после успешной проверки; готовая модель — в D/models/cosyvoice3.

На Windows ONNX-анализ образца работает на CPU. Основной синтез запускается
в отдельном процессе после выгрузки ASR и освобождает VRAM при завершении.
Адаптер загружает state_dict через CPU, хранит LLM в FP16, веса flow и вокодера
в FP32, использует официальный autocast. Это локальная адаптация загрузки весов
для экономии памяти; TensorRT, vLLM и JIT не используются.
`COSYVOICE_DEVICE=cpu` отключает GPU только для CosyVoice; по умолчанию auto.
Для текста применяется наш нормализатор; повторный upstream text frontend выключен.
Один подготовленный голос используется для всех частей текущего запроса;
между запросами он не кэшируется. Выход: WAV PCM16, 24 кГц, моно.

API: `POST /api/tts` с
`{"engine":"cosyvoice","speaker":"clone-...","text":"Новый текст","ref_text":"Текст образца"}`.
Пустая расшифровка возвращает 400 до выгрузки ASR. Авторизация, общий busy-слот,
лимит 2000 символов, таймаут 15 минут и удаление временных запросов общие с Qwen.
Неперехваченная ошибка потока генерации завершает только worker, возвращая
диагностику в `D:\Games\STT_TTS_project\logs\cosyvoice-worker.log`.

Проверка на RTX 3050 Laptop 4 ГБ: русский текст 111 символов, синтетический
образец 12,803 с. Результат — 9,2 с аудио за 128,337 с с загрузкой моделей;
пик выделенной памяти PyTorch 3113,2 МиБ. Полный расход видеокарты во время
синтеза доходил примерно до 3952 МиБ из 4096. Для ограничения пиков новый
текст делится на части до 120 символов. В контрольной расшифровке Qwen ASR
полностью восстановил исходный русский текст. Это проверка содержимого,
а сходство тембра нужно оценивать прослушиванием. Файлы проверки:
`D:\Games\STT_TTS_project\results\cosyvoice-test.wav`, соответствующие JSON
и `cosyvoice-test-asr.json`. Модель закреплена на
`29e01c4e8d000f4bcd70751be16fa94bf3d85a18`. Тесты проекта проходят.
Повторный запрос из браузера дал те же 9,2 с аудио за 99,631 с. Проверены
воспроизведение (плеер перешёл в состояние «Пауза»), длительность и совпадение
ссылки скачивания WAV с источником аудиоплеера. Снимок интерфейса:
`D:\Games\STT_TTS_project\results\cosyvoice-interface.png`.

## Доступ по сети

По умолчанию сервер слушает только localhost. Для доступа с других устройств
нужны HOST, API_TOKEN и HTTPS-прокси. Например:

```powershell
$env:HOST='0.0.0.0'
$env:API_TOKEN='YOUR_LONG_RANDOM_SECRET'
.\start.ps1
```

Для HTTP API передавай `Authorization: Bearer ...`; браузерный UI имеет поле
токена. Микрофон на удалённом устройстве требует HTTPS. Firewall/TLS, персональные
аккаунты и ограничение запросов для production ещё не настроены.

## Восстановление окружения

Методика сравнения ASR, TTS и клонирования на этом ноутбуке: `docs/evaluation-methodology.md`.

Используется Python 3.12, PyTorch 2.8.0 + CUDA 12.6, torchaudio той же версии,
qwen-asr 0.0.6. Исходный runtime Qwen — Transformers 4.57.6.
Восстановление: `scripts/setup.ps1`. Скрипт направляет кэши установок на D.
После установки: `scripts/download-model.ps1` — выбирает текущий commit модели,
скачивает в HF-кэш на D и записывает конкретную ревизию в `models/asr.json`.
Обычный сервер работает из этого snapshot без сетевой загрузки весов.
Повторный вызов download-model может выбрать более новую ревизию — это явное обновление.

## Лицензии

Собственный код — Apache-2.0. Qwen3-ASR, Qwen3-TTS, MOSS-TTS-Nano и CosyVoice 3:
код и выбранные веса (включая ONNX-аудиокодек MOSS) — Apache-2.0.

свои лицензии; полная сборка не имеет единой Apache-лицензии на каждую библиотеку.

CosyVoice установлены в отдельных окружениях, потому что им нужны разные

`uv pip freeze --python D:\Games\STT_TTS_project\envs\py312\Scripts\python.exe`
(для TTS замени `py312` на `tts` или `cosyvoice3`).
